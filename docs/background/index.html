Agent loop pattern

Stages 10 and 13 share the same generate–execute–critique–repair loop, built from CodexModel (LLM) and CodeRunner (subprocess). Stage 14 reuses the runner for its parameter edits. If you understand this loop, you understand the core of the system.

Generated file layout

CodeRunner.add() prepends a fixed header. EvaluationAgent later splits the file on the marker line to recover the LLM part.

# initialize paths
from paths import dataDir
from paths import sandboxDir
from paths import modelsDir

# Generated code starts here
<LLM code>

Execution environment

Interpretersys.executable (same venv) cwdproject root PYTHONPATHproject root prepended MPLBACKENDAgg stdinDEVNULL Timeout1800 s → error dict Return{"operation": "success"|"error", "output": str}

A non-zero exit returns stderr. Success returns stdout, or "No output".

State held by the agent

  • lastGeneratedCode: fed to fixCode()
  • lastReasoning: the "fix prompt" from reason()
  • No history of earlier attempts. Each fix sees only the latest code and the latest diagnosis.

Known issues

  • C1An LLM decides pass/fail, even for checks that are pure code (dtypes, nulls, exit code, file exists).
  • D2Generated code runs with full user permissions and network access. sandbox/ is only a folder.
  • C3No temperature or seed, no log of prompts, tokens or cost, no retry on API errors.

Startup & dataset path

User I/Omain.py · main()

A Click command. Starts a timer, makes sure the shared config file exists, prints the banner, and asks for the dataset path.

Inputs

  • Dataset path typed by the user

Outputs

  • configuration/configuration.json = {} (only if missing)

Config reads

—

Config writes

file created, no keys

How it works

  1. sys.dont_write_bytecode = True is set before the other imports.
  2. ensureConfiguration() creates configuration/ and an empty JSON file if absent. An existing file from a previous run is not cleared.
  3. httpx/openai loggers are silenced to WARNING.
  4. questionary.path() loops until the path exists. Ctrl-C/None prints "Cancelled." and exits.

Alternative entry points with the same flow: main2.py (plain input() plus DEBUG logging to sandbox/debug.log, with a step() wrapper that times each stage and diffs the config) and app.py (plain input(), INFO logging).

Known issues

  • E1Three near-identical entry points, and main.py duplicates the full pipeline for each mode.
  • E2Leftover configuration.json from a previous run leaks into the new one (keys like endPoint, columnNames).

Consultation dialogue

LLM callUser I/OInteractive onlyagents/consultant.py · Consultant.nextQuestion()

A chat loop that asks one question at a time until six requirements are answered.

Inputs

  • First turn: "Dataset Path: <path>"
  • Later turns: user's free-text answer

Outputs

  • Consultant.history: list of {user, assistant}

Config reads

—

Config writes

—

The six requirements

  1. Task type
  2. Explainable model?
  3. Evaluation metric
  4. Minimum score
  5. Written report?
  6. Deploy the model?

How it works

  1. Calls the LLM with the system prompt, the full history as alternating user/assistant messages, and the new input.
  2. If the reply is [OFFTOPIC], the turn is not added to history, and the last real question is repeated with a canned prefix. The fallback is "Should the model be explainable?".
  3. If the reply is [DONE], the turn is stored and None is returned, which ends the loop.
  4. Otherwise the question is stored and printed as "🤖 Bot:".

Known issues

  • —No turn limit. Termination depends entirely on the LLM saying [DONE].

Task-type inference

DeterministicAuto onlymain.py · inferTaskTypeFromTarget()

A rule-based heuristic on the target column. If stage 05 returned no target, the task becomes clustering.

Decision rules (in order)

ConditionResult
target is Noneclustering
unique values == 2binary-classification
numeric ratio > 0.95 and unique > 20 and unique ratio > 0.05regression
otherwisemulti-class-classification

Known issues

  • A2Never returns time-series or anomaly-detection, although the README claims support for them.
  • B8An ordinal 0–10 score becomes 11-class classification. On large datasets, a regression target with low cardinality becomes classification.

Exploratory data analysis

Deterministictools/eda.py · EDA.run()main.py · runEDA()

The only large deterministic component (~1,100 lines). It produces a Markdown report, and every downstream LLM uses that report as its "eyes" on the data. See EDA internals for the rules.

Inputs

  • Dataset path, targetCol, taskType
  • configuration/edaconfig.py (readers, allowed task types)

Outputs

  • sandbox/<stem>eda.md

Config reads

  • Interactive: targetCol, taskType (from file)

Config writes

—

How it works

  1. Skipped entirely if taskType is falsy.
  2. The constructor validates taskType against allowedTaskTypes and raises ValueError otherwise.
  3. loadData(): CSV/TSV with delimiter sniffing and a UTF-8 → latin-1 fallback. Other formats go through edaconfig.readers. It rejects empty data, all-NaN data, or a missing target.
  4. inferTypes() labels every column (id_like, boolean, datetime, text, categorical, numeric_discrete, numeric_continuous). String columns that are >90% numeric get converted in place.
  5. Seven sections are built, and warnings are collected along the way. The result is written with tabulate tables.

Known issues

  • —Only the Markdown report is persisted. No machine-readable profile (JSON) exists for code to use, so downstream consumers re-parse free text.

Preprocessing plan

LLM callagents/planner.py · Planner.createPreProcessingPlan()

An LLM writes a plain-English plan. A second LLM (stage 10) turns it into code.

Inputs

  • EDA report

Outputs

  • sandbox/processingplan.md

Config reads

  • dataFile, taskType, targetCol

Config writes

—

Contract the plan must describe

  1. Sections: Imports → Load Data → Custom Transformers → Pipeline → Fit and Save.
  2. Load dataDir / dataFile. Save to dataDir / "<stem>_processed<ext>" with index=False.
  3. One scikit-learn Pipeline. Every step is a custom BaseEstimator + TransformerMixin, and the pipeline takes raw rows.
  4. The target is split off before fitting. Text labels are mapped to integers outside the pipeline, and the target is re-attached in the output file.
  5. Robustness: X.copy(), errors='ignore' on drops, errors='coerce' on casts, missing-column injection.
  6. The fitted pipeline is saved with cloudpickle to modelsDir / "preprocessor.pkl".

  • C5The target label mapping is never persisted, so the API cannot return original labels.
  • C4"Do not use comments" conflicts with codexcodeprompt.md ("add section comments").

Preprocessing agent loop

Runs generated codeLLM ×3 rolesagents/processoragent.py · ProcessorAgent.preprocess(maxAttempts=10)

Generates sandbox/processing.py from the plan, runs it, and repairs it until an LLM critic accepts the processed data. Follows the agent loop pattern.

Inputs

  • sandbox/processingplan.md
  • Raw dataset in data/

Outputs

  • sandbox/processing.py
  • data/<stem>_processed.csv
  • models/preprocessor.pkl

Config reads

  • dataFile, taskType, targetCol

Config writes

  • processedDataFile
  • preprocessorFile (default preprocessor.pkl)

How it works

  1. act(): coder.code("Dataset Path: <dataFile>\n\n" + plan), then write the file and run it.
  2. reason() on success: getDataInfo() reads the processed CSV, writes processedDataFile/preprocessorFile to the config, and sends {taskType, targetCol, processedColumns: {rowCount, columns: {col: {non_null_count, dtype}}}} to the critic.
  3. reason() on error: the critic receives the raw stderr.
  4. Critic rules: supervised data must contain the target, all columns must be numeric, and there may be no nulls. Unsupervised: all numeric, no nulls, no target needed.
  5. fail leads to fixCode(lastGeneratedCode, lastReasoning) and another run. The loop gives up with RuntimeError after 10 attempts.

LLM

Generate
codexcodeprompt.md → raw Python
Critic
processorreasoningprompt.md → ReasoningResult{condition, prompt}
Repair
codexfixprompt.md → full fixed file

Known issues

  • C1"All numeric, no nulls, target present" is a deterministic check, but an LLM judges it.
  • D2Unsandboxed execution.
  • —The processed-file name is derived from dataFile, but the file is never checked for existence before reading. A wrong name crashes instead of feeding the fix loop.

Train / test split

Deterministictools/datasplitter.py · split()

Splits the already processed data with sklearn.train_test_split.

Inputs

  • data/<processedDataFile>
  • constants.json: trainSplit 0.8, testSplit 0.2, seed 42

Outputs

  • data/train.csv, data/test.csv
  • data/val.csv only if val share > 0

Config reads

  • processedDataFile

Config writes

  • trainFile, testFile, (valFile)

How it works

  1. validationSplit = 1 − train − test. With the current constants this is ≤ 0, so no validation set is created.
  2. Test split first. If validation > 0, it is carved from the remainder with val / (1 − test).
  3. Shuffled, not stratified, same seed for both splits.

Known issues

  • B1The split happens after preprocessing was fitted on everything.
  • B2No validation set, so tuning later uses the test set.
  • B3No stratification for imbalanced classes. Time series are shuffled.

Evaluation & tuning loop

Runs generated codeLLM ×2 rolesagents/evaluationagent.py · EvaluationAgent.tune()

Scores the ONNX model on train and test. If the threshold isn't met, it asks the LLM for parameter changes, has another LLM rewrite train.py, and retrains.

Inputs

  • models/model.onnx
  • data/train.csv, data/test.csv
  • sandbox/train.py (after the marker)

Outputs

  • sandbox/tuning.json
  • possibly retrained model.onnx / rewritten train.py

Config reads

  • desiredMetric, targetCol, minScoreRequirement, trainFile, testFile, modelFile

Config writes

—

How it works (for i in range(tuningIterations = 3))

  1. Load the ONNX session. Predict with the features as float32. A single-input model gets the whole matrix; a multi-input model gets one column per input name. Only outputs[0] is used.
  2. computeScore() on train and test, rounded to 2 decimals. Lower-is-better metrics: MAE, MSE, RMSE, MAPE, SMAPE, Log-Loss, Davies-Bouldin.
  3. If both scores meet minScoreRequirement, append {finalScores} and stop.
  4. Annotate the previous history entry with scoreBefore, scoreAfter and helped (both scores improved).
  5. Query: iteration 0 sends train code + scores + target. Later iterations send the full history + scores + target.
  6. suggestParameters() (JSON mode) → {"param": {"current": x, "new": y}}.
  7. act(): tuneParameters() rewrites the code ("only change parameter values"), then train.py is overwritten and run.
  8. After the loop, the history is dumped to tuning.json.
[{"iteration": 1, "parameterChanges": {...},
  "scoreBefore": {"train": .., "test": ..}, "scoreAfter": {...}, "helped": true},
 …,
 {"finalScores": {"train": .., "test": ..}}]   // only if threshold met

LLM

Suggest
evaluationprompt.md → JSON object (no schema)
Rewrite
codexcodeprompt.md + 4 inline constraints → full Python

Known issues

  • B2The test set drives tuning, so there is no unbiased final score.
  • B4outputs[0] holds labels, so ROC-AUC, Log-Loss and AP are computed from hard labels. Weighted averaging everywhere. MAPE divides by zero. Anomaly and clustering metrics receive features as true.
  • B5The result of act() is ignored, so a crashed retrain goes unnoticed. The last iteration's model is never scored but still gets deployed.
  • E5None metric or threshold → AttributeError / TypeError.

Remote / SSHif deployment == truemain.py · checkAndDeploy()tools/transfer.pytools/deployer.py

Packs the model into vm/, uploads it over SFTP, starts a FastAPI server on the VM, and exposes it through ngrok.

How it works

  1. copyArtifactsToVm(): every file and folder in models/ plus configuration.json is copied into vm/.
  2. transfer.py: SSH as root with a password (AutoAddPolicy), mkdir /root/vm, upload vm/** recursively.
  3. deployer.py:
    • If ngrok is missing, add the apt repo (buster), apt install ngrok, and set the auth token.
    • Check that ls vm contains api, configuration, model, prediction, preprocessor, requirements.txt (substring match). If not, exit(1).
    • Create venv dslab1 if absent. pip install -r requirements.txt (timeout 300 s).
    • Kill whatever holds port 5000, start uvicorn in the background (log /tmp/api.log), wait 3 s.
    • Start ngrok in the background (log /tmp/ngrok.log), wait 5 s.
    • Poll localhost:4040/api/tunnels up to 10× (2 s apart) for the https tunnel, then write it to config as endPoint.

Report sections

1 · Overview

File size, rows/cols, memory, missing %, duplicate rows (+ first 3 indices), type breakdown, per-column summary table.

2 · Target

Classification-like: class table, imbalance ratio & level. Regression/time series: mean, median, std, min, max, skew, kurtosis, 5/25/75/95th percentiles, IQR outliers.

3 · Per-column

Type-specific: numeric (IQR & z>3 outliers, percentiles, negatives), categorical (top values), boolean, datetime (range, gaps, monotonic), text (lengths), id-like (samples).

4 · Missing values

Per-column counts, co-missing row patterns.

5 · Correlations

Pearson |r| > 0.5 between numerics. Cramér's V > 0.3 between categoricals (≤ 50 levels). Target association: Pearson / Cramér's V / point-biserial > 0.1.

6 · Outliers · 7 · Warnings

Outlier summary per numeric column. All collected warnings grouped by missing, outlier, correlation, cardinality, skew, imbalance.

Serving & API

What runs on the VM after stage 16: vm/api.py + vm/prediction.py, with dependencies from vm/requirements.txt.

Endpoints

MethodPathReturns

The request body is a list of objects. The schema is created at startup with pydantic.create_model: every name in columnNames is a required field of type Any.

Prediction path

  1. At import: joblib.load(preprocessor.pkl), ONNX session, first input name, config.
  2. pd.DataFrame(rows)[columnNames]
  3. preprocessor.transform() → dense → float32
  4. time series: reshape to (1, n, f)
  5. session.run() → outputs[0].tolist()
POST /predict
[ { "feature_1": 1.5, "feature_2": "value", ... } ]
→ { "prediction": [0] }
